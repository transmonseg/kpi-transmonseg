## Tipologia consolidada (5 padrões observados)

### Padrão A — CD-only (≈ 30% das placas-dia)
Veículo ficou todo o dia em BASE BENASSI (lat -22.827, lng -43.337). Total de paradas tipicamente 5–25, todas com Local = `BASE BENASSI - BASE BENASSI`. Significados possíveis:
- Veículo em manutenção / sem motorista
- Veículo de apoio (carga/descarga interna)
- Motorista folgou mas veículo não saiu

**Exemplos diários comuns**: ALS-4H33, AMI-1562, AMR-9986, DDI-6J90, DJB-6D42, EOF-4331, EOF-4951, EVU-7F71, EZU-9325, EZU-9D26, EZU-9D27, EZU-9J51, FTV-6F42, FSE-2J12 — esses retornam todo dia como CD-only nos 5 relatórios.

**Implicação pro matcher**: NÃO devem aparecer no KPI como cumprindo escala. Se cair em alguma rede, é erro do matcher (provavelmente Bug 1 — GPS clonado via `scorePair < Infinity`).

### Padrão B — Mono-loja (≈ 25% das placas-dia)
1 saída do CD, 1 a 3 paradas em UMA loja específica (mesmo código), volta pro CD. Caso "feliz" — matching limpo.

**Exemplos**: AKZ-2745 dia 18 (SENDAS MEIER + PAX GUADALUPE), AKZ-2594 dia 18 (SENDAS FREGUESIA LJ 28 + ZS 19 Copacabana), CXA-7B36 dia 18 (SUPERPRIX GRAJAÚ 04 + 08), KMY-5561 dia 18 (CARREFOUR BARRA + PAX REALENGO).

### Padrão C — Multi-loja mesma rede (≈ 20% das placas-dia)
Veículo serve várias lojas de uma rede só. Caso típico:
- **PRINCESA Cabo Frio**: AWA-6B40 dia 18 visitando 560017 + ARRAIAL DO CABO 1/2/3
- **PRINCESA Buzios**: dedicado roteiro 1+2+3
- **ZONA SUL Leblon/Ipanema**: 9039007 + 9039011 + 9039015 + 9039008 etc.

### Padrão D — Multi-rede no mesmo dia (≈ 15% das placas-dia)
Veículo cruza eixos diferentes: PRINCESA Rio das Ostras + FEIRA NOVA + SENDAS Petrópolis. Comum no eixo Av Brasil.

**Exemplos**: JAJ6B36 dia 18 (PRINCESA RIO DAS OSTRAS + BARRA SÃO JOÃO + SENDAS BOTAFOGO + LTU CDD HUMAITA), KNS-8D26 dia 18 (SENDAS BOULEVARD + FEIRA NOVA BOA DICA PIABETÁ + CAB PETROPOLIS sobreposto), KOA-6A27 dia 18 (PREZUNIC VILAR DOS TELES + FEIRA NOVA COELHO DA ROCHA + FEIRA NOVA CERAMICA).

### Padrão E — Rota gigante (≈ 10% das placas-dia)
Geofence Unitrac é uma ROTA (raio 20-50km). Não dá pra cravar loja individual via código — precisa matching geo (lat/lng + raio loja).

**Exemplos**: DZX-3H55 dia 18 (`ROTA BOTAFOGO` só), EAK-6G02 dia 18 (`ROTA NITEROI/MARICA`), KNZ-5B07 dia 18 (`ROTA NOVA IGUACU`), KOH-0H77 dia 18 (`ROTA CAMPO GRANDE`).

## Padrões problemáticos detectados

### Geofences overlapping (paradas com múltiplos códigos)
~15% das paradas têm 2-3 códigos no campo Local separados por vírgula. Causa: a região tem múltiplos geofences sobrepostos no Unitrac.

**Casos típicos:**
- `BASE BENASSI - BASE BENASSI, 7012010 - CAB - PETROPOLIS` — todo veículo que passa no CD ganha o tag CAB junto (KNS-8D26)
- `BASE BENASSI, 11139000 - EMANUEL COMÉRCIO PEDRA DE GUARATIBA, 17659000 - O BOM ATACADISTA` — placa KNC-5J75
- `BASE BENASSI, 2018019 - ROTA NOVA IGUACU` — KNZ-5B07
- `BASE BENASSI, 9039124 - 47- ZONA SUL` — CYB-3B90
- `BASE BENASSI, 23080000 - MERCADO SANTO AGOSTINHO, 15755000 - MERCADO ITAGIBA COSMOS` — EYL8B91

**Implicação**: no parsing precisa preferir o código que NÃO é ROTA GIGANTE quando há overlap, e descartar BASE BENASSI / FORA DE BASE.

### "FORA DE BASE E LOCAL DE SERVIÇO" (≈ 50% das paradas)
Maioria das paradas reais nas lojas não tem geofence Unitrac. Precisam matching por lat/lng + raio cadastrado.
